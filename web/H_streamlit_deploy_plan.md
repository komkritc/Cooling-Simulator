# H — Streamlit Community Cloud deployment plan

## 1. Target

`https://share.streamlit.io/<github-user>/<repo>` — Streamlit Community Cloud,
free tier, deployed automatically from a GitHub branch. No server to run, no
container, no Cloudflare account. (Community Cloud also supports a custom domain
on paid plans; not needed for v1.)

## 2. The one blocking decision: what becomes public

Community Cloud **requires a GitHub repository** and free apps are deployed from a
**public** repo (private repos need a paid Standard seat, ~$0.05/h, or "Streamlit
in Snowflake"). You asked for local-only git, so pick one:

| Choice | What is published | Notes |
|---|---|---|
| **(a) Slim public mirror repo** *(recommended)* | `streamlit_app.py`, `webapp/`, `studio/core/` (vendored copy or subtree), `data/lut_*.csv/.npz`, `lut_registry.json`, `baselines/golden.json`, `web/tests/`, sample bundle. **No** `studio/gui/`, no raw VAMPIRE tree, no docs A–E | ~12 MB repo; you keep the real project local-only. A tiny `sync.sh` copies the vendored `studio/core` from the local app so the mirror never drifts silently |
| (b) Make the whole `ME_Cooling_LUT/app` repo public | everything, incl. the 8.3 MB LUT and docs | simplest, but publishes planning docs and test artifacts |
| (c) Private repo + paid Streamlit Standard | nothing public | hourly cost, needs a billing account |
| (d) Self-host Streamlit (Docker) on the lab server / any VPS | nothing | no GitHub at all; keeps the local-only rule; you get a URL like `mintlab.example.org/me-cooling`; needs nginx + systemd/Docker + TLS; ~1 h setup |

`H` assumes (a). If you choose (d), everything else in this plan still applies —
only §4–§6 change (Dockerfile + reverse proxy instead of the dashboard).

Mirror repo layout (deployment root = repo root, entry `streamlit_app.py`):

```
me-cooling-web/                 <- public GitHub repo (mirror, generated by sync.sh)
  streamlit_app.py              thin entry: sys.path bootstrap + webapp.layout.main()
  webapp/                       UI layer (from web/webapp/)
  studio/core/                  vendored copy of the Qt-free core  (checksum-pinned)
  data/lut_current_rf_1-10nm_dD0p1.csv
  data/lut_current_rf.npz       fast-load twin (tools/make_lut_npz.py)
  studio/core/lut_registry.json
  baselines/golden.json
  sample/rate_{200..6000}.json  sample bundle (aggregated, see F §5)
  requirements.txt  .streamlit/config.toml  runtime.txt
  tests/                        golden + web-parity tests (also run in CI)
  tools/sync_from_local.sh      copies studio/core + LUT + golden from the local app,
                                prints the SHA-256 of each copied file
```

Guard rail: `sync_from_local.sh` writes `VENDORED.sha256` with the hash of every
vendored core file; `web/tests/test_vendored_hash.py` fails the CI build if a copy
is edited in the mirror (prevents the classic "two diverging physics copies" bug).

## 3. Pinned requirements (`web/requirements.txt`)

```
streamlit==1.4x.x        # pin exact at build time; Streamlit minor bumps change widgets
numpy==2.5.5             # pinned, as in the desktop requirements
matplotlib==3.11.1       # pinned: byte-identical figure baseline
```

Explicitly **excluded**: `PySide6` (hundreds of MB, useless on the server, and it
is the main reason a deploy fails on the free tier). Note: `app/.venv` is a
symlink to `Cooling_Model_Comparison/cooling_simulator/.venv`, i.e. **shared with
another project** — so Streamlit must be installed in a *separate* venv
(`web/.venv`), never into the shared one, or that project's pinned environment
gets polluted.

Also pin `runtime.txt` → `python-3.12` to match the tested interpreter
(local Python 3.12.3).

## 4. Configuration (`web/.streamlit/config.toml`)

```toml
[theme]
base = "light"
[browser]
gatherUsageStats = false
[server]
headless = true
maxUploadSize = 50          # MB, VAMPIRE zip uploads
enableXsrfProtection = true
[fileUpload]
maxUploadSize = 50
```

Header/footer: put the version string from `studio/version.py` (it shells out to
`git tag`; on Cloud there is no git dir → it already falls back to
`VERSION_FALLBACK`, so we pass the version via `web/VERSION` or an env secret
instead of relying on git).

## 5. Free-tier limits and what they mean for this app

| Limit (free Community Cloud) | Effect on the app | Mitigation |
|---|---|---|
| 1 GB RAM, 1 CPU per app | numpy+matplotlib+streamlit ≈ 250–350 MB; a 25-seed rate parse ≈ +50 MB | LUT as npz (float32), parse only the uploaded rate, cap concurrent rates (6), drop `run_stdout.txt` from parse |
| App **sleeps** when idle; cold start 10–30 s | first visitor waits | import lazily (`st.cache_resource` for LUT), keep the top-level import set minimal, "keep awake" pinger only if it becomes annoying (not free-friendly) |
| Repo must be public (free) | see §2 | mirror repo (a) |
| No persistent disk (resets on redeploy/idle) | record files cannot live on the server | return records as an in-memory ZIP download (J §R7) |
| Secrets via dashboard (`st.secrets`) | none needed for v1; sample-data URL or optional storage later | keep the app secret-free |
| Concurrent users share one process | 6-rate sweep × 2 users is still ~100 ms of CPU | results cached per session; run in a `st.spinner` block |
| No auth on free tier | anyone with the URL can use it (compute + sample data) | link discipline; optional simple passphrase in `st.secrets` (not real security, J §R3) |

## 6. Deploy procedure (once you approve §2)

1. `git init` the mirror, `tools/sync_from_local.sh`, commit, push to GitHub
   (needs a GitHub account + token; I can prepare everything and give you the
   exact 5 commands, or run them if you supply the remote).
2. share.streamlit.io → *Sign in with GitHub* → *New app* → pick repo/branch/
   entry file `streamlit_app.py` → *Deploy*. Logs appear in the app's
   "Manage app" panel; every push to the branch redeploys automatically.
3. CI (optional but recommended): GitHub Actions running `pytest tests/`
   (golden + vendored-hash + parity) on every push, so a physics change that
   breaks the six validated numbers can never reach the public URL.
4. Versioning: tag the mirror per release; the header shows the tag; a
   `?v=` query param or a "About" expander shows the core SHA-256 so a reader of
   a paper can match the exact code that produced their figure.

## 7. Rollback / safety

* Redeploy = pick a previous GitHub release in the dashboard (instant).
* The local Qt app is untouched → if the web app misbehaves, the desktop app and
  the validated records remain the source of truth.
* `VENDORED.sha256` + golden tests are the drift alarms; any change to
  `studio/core` must be made **locally first**, then re-synced, never edited in
  the mirror.
